# 查询与统计测试场景

## KS-QUERY-001 单条件筛选准确性

对于 status、priority 等枚举筛选，应准备至少两个不同值的数据，然后分别筛选，验证：
- 返回结果全部满足条件
- 应命中的目标数据确实被返回
- 其他枚举数据没有混入

不能只判断 HTTP 200 或结果非空。

## KS-QUERY-002 多条件组合

存在多个筛选条件时，至少覆盖一组组合：

```text
status + priority
status + keyword
priority + keyword
```

组合查询需要验证交集语义，而不是分别验证每个单条件后默认组合一定正确。

## KS-QUERY-003 关键字搜索

关键字搜索至少准备：
- 标题命中
- 描述命中
- 不命中
- 与其他筛选条件组合

如果需求没有明确大小写、模糊匹配或 trim 规则，不得由知识库擅自确定这些业务语义。

## KS-STAT-001 统计值从源数据反算

Dashboard/统计接口不能只检查“有数字”。测试应从真实源数据独立计算期望值，再与展示值比较。

例如任务统计可以校验不变量：

```text
tasks = completed + unfinished
```

并分别核对 completed、unfinished 与任务列表真实状态数量。

## KS-STAT-002 变更后的统计

统计测试至少执行一次数据变更：
- 新增
- 状态变更
- 删除

然后重新查询统计值，避免只验证初始化快照正确。
