# 输入边界与枚举测试场景

## KS-VAL-001 必填字符串

当需求声明字符串不能为空时，不应只覆盖正常值和空字符串。至少考虑：
- 正常字符串
- 空字符串 `""`
- 仅空格、Tab 或换行组成的字符串
- 前后包含空白但主体有效的字符串
- 如果存在长度上限：max-1、max、max+1

如果系统存在 trim/normalize 行为，应校验“校验发生在规范化之前还是之后”，避免输入先通过长度或非空校验，随后被规范化为空值。

## KS-VAL-002 前后端约束一致性

同一业务字段同时存在 UI 和 API 入口时，边界约束必须做一致性检查：
- UI 拒绝而 API 接受
- API 拒绝而 UI 可以提交
- UI 与 API 的最大长度不同
- UI 自动 trim，但 API 不 trim，或反之

测试用例应分别覆盖 UI 和 API，而不是用单条用例代替两个入口。

## KS-VAL-003 枚举字段

当需求明确合法枚举集合时，至少覆盖：
- 每一个合法枚举值
- 一个集合外非法值
- 空值/缺失值（如果接口允许构造）
- 大小写变化（仅在协议可能受影响时）

非法值不应被静默映射成另一个合法值。若项目接口规范约定参数错误返回 4xx，应显式验证错误响应，而不是只验证结果为空。

## KS-VAL-004 组合边界

多个输入条件同时存在时，不要只做单字段边界。至少选择一组组合场景验证：
- 一个字段有效 + 一个字段非法
- 边界值 + 状态/优先级筛选
- 空字符串/空白字符串 + 其他合法字段
