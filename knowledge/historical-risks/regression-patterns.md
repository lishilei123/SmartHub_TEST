# MiniTask 类项目历史回归风险

这些内容是历史风险模式，不代表当前版本一定存在缺陷。

## KR-001 输入规范化风险

历史上必填字段容易只校验原始字符串长度，随后 trim 后变成空字符串。涉及项目名、任务标题等文本字段时，提高空白字符场景优先级。

## KR-002 关联删除风险

父资源删除成功并不代表关联数据已经清理。项目/任务等父子关系变化时，优先检查孤儿数据和统计残留。

## KR-003 状态回退风险

状态机实现常见问题是接口只检查“目标状态属于合法枚举”，却没有校验“当前状态 → 目标状态”这条边是否合法。

## KR-004 筛选字段映射风险

枚举筛选常见回归包括参数映射错误、复制粘贴导致某个值映射成另一个值，以及非法参数被静默吞掉。

## KR-005 统计 off-by-one 风险

Dashboard 容易出现固定偏移、缓存未刷新或 completed/unfinished 计算不一致。统计场景优先采用源数据反算，不只看单个数字。

## KR-006 UI 确认交互风险

删除类操作经常在 UI 重构后丢失二次确认，但后端删除接口仍然正常，因此必须单独保留 UI 交互检查。

## KR-007 前后端边界漂移

字段长度、必填、枚举限制可能只在前端或后端更新一侧。版本回归时应优先比较两个入口的实际约束。
